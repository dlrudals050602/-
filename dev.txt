1. 목표 라우팅 및 페이지 구조 설계
전체 화면을 인증 전(Public) 영역과 인증 후(Protected + Layout 적용) 영역으로 분리합니다.

/ (Root)
├── [Public Routes] - 하단 바 미표시
│   ├── /login           : 로그인 및 회원가입 (AuthView)
│   └── /reset-password  : 비밀번호 재설정 (ResetPasswordForm)
│
└── [Protected Routes] - BottomLayout 적용 (하단 네비게이션 바 고정)
    ├── /leaves          : 1. 내 출타 정보 보기 & 신청 (MyLeavesPage)
    ├── /calendar        : 2. 전체 출타 캘린더 (CalendarPage)
    └── /profile         : 3. 내 정보 관리 (ProfilePage / 기존 MainView)
2. 단계별 리팩토링 전략
1단계: 라우팅 라이브러리 도입 및 인증 전역 상태화 (AuthContext)
react-router-dom을 적용합니다.

App.js에 밀집되어 있던 user, userProfile 상태와 Supabase onAuthStateChange 리스너를 AuthContext로 분리하여 앱 전체 어디서든 유저 정보를 접근 가능하게 만듭니다.

미인증 사용자가 보호된 페이지 접근 시 /login으로 자동 리다이렉트하는 ProtectedRoute 컴포넌트를 작성합니다.

2단계: 공통 레이아웃 및 하단 네비게이션 바 작성 (BottomLayout)
인증된 유저 전용 레이아웃 컴포넌트를 생성합니다.

상단/중앙 영역은 <Outlet/>을 통해 선택된 탭 페이지를 렌더링하고, 화면 최하단에 모바일 앱 스타일의 Bottom Navigation Bar를 고정(position: fixed 또는 Flexbox Layout)합니다.

탭 아이콘 구성:

📄 내 출타 정보: /leaves

📅 캘린더: /calendar

👤 내 정보: /profile

3단계: 기존 단일 컴포넌트들을 독립 페이지로 분리
MyLeavesPage (/leaves): 본인의 출타 이력 조회 및 LeaveForm을 통한 출타 신청 기능 통합.

CalendarPage (/calendar): CalendarView 중심의 전체 출타 현황판.

ProfilePage (/profile): 기존 MainView의 계정 설정 및 로그아웃 기능 분리.

4단계: 출타 데이터(Leaves/Holidays) 공유 상태 최적화
페이지를 전환해도 leaves 및 holidays 데이터가 매번 재요청되지 않거나 필요 시에만 동기화되도록, 데이터를 공통 컨텍스트(LeaveContext)로 끌어올리거나 각 페이지 진입 시 캐싱 로직을 점검합니다.
